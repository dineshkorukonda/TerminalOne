# Pre-beta security review

Issue #44 reviews the current terminal architecture, packaging changes in this PR, and the Phase 4 developer-data boundary in PR #65. Final qualification must use the integrated source commit and actual artifact. This is a focused engineering review, not an independent penetration test or a security certification.

## Assets, actors and boundaries

Protect local commands/output/history, project metadata, signing credentials, renderer isolation and owned-process cleanup. Terminal output, clipboard/import data, shell metadata and renderer requests are untrusted inputs. A user-run shell has the user's normal Windows privileges: it can already access same-user files and processes. Job Objects are lifecycle ownership, not a sandbox against malicious commands, service launches or external brokers.

Main authorizes exact webContents/main-frame/document senders and complete argument/schema shapes. Preload exposes named capabilities only. Renderer has context isolation, no Node integration, denied navigation/popups/permissions and strict local script CSP. Trusted inline styles support xterm metrics; they do not enable inline/eval scripts. Command output is written through xterm, not HTML. External links have an exact allowlist. User-entered raw terminal input executes only in the explicitly active shell.

Utility RPC has bounded pending requests and chunked output acknowledgment/backpressure. Native PTYs and children live in kill-on-close jobs watched by retained main/utility handles. The package requires ASAR integrity and disables Node mode/options/inspection fuses, while native helper/addon paths remain unpacked. Unsigned artifacts and same-user native-file tampering remain release risks until signing/OS policy is reviewed.

Phase 4 history is explicit opt-in complete-command capture, never an execution authorization or trusted prompt-state observation. Same-user processes can inspect/alter their own integration; nonce-scoped frames prevent accidental cross-session parsing, not a malicious same-user actor. Private input requires confirmed no-save integration, failed private integration exits, app history has bounded retention and coalesced writes, and imports contain no executable arguments/environment/commands. Draft acceptance/explanation never submits PTY input. The optional static explanation path has no provider or network dependency. No cloud content submission is implemented.

## Findings and treatment

| Finding                                                                                  | Treatment                                                                                                                                                        | Residual risk                                                                                                  |
| ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Private input could precede no-save hook readiness during feature development            | Phase 4 main refuses private writes until integration readiness; renderer also disables input; failed installation exits; focused unit/native tests              | An authorized shell can change its own policy; not a same-user sandbox                                         |
| History write bursts could queue unbounded snapshots                                     | Coalesced serial writes, record/aggregate character bounds and bounded preferences requests                                                                      | Local plaintext history still requires explicit opt-in; filters cannot identify all secrets                    |
| Encoded settings could exceed their read limit; failed renames could retain temp history | Phase 4 enforces the UTF-8 byte limit before save and removes temporary files on failure; regression cases cover both                                            | Filesystem failures can prevent successful saving/deletion and must not be represented as completed operations |
| New builder dependency brought an advisory through an old proxy dependency               | Pin a scoped global-agent 4.1.3 override for @electron/get 3.1.0; bootstrap API checked; repeat npm audit                                                        | Build-tool supply chain still requires locked versions, integrity and maintenance                              |
| Powerful Electron production defaults                                                    | Actual production fuse verification, ASAR integrity/native-path checks and installed-app exercise without debugging flags                                        | Unpacked binaries/unsigned distribution are not authenticated; no signing claim                                |
| Invalid tablist children found by axe                                                    | Move close control outside the ARIA tablist and rerun automated/keyboard flows                                                                                   | Manual Narrator evidence remains required                                                                      |
| Installed renderer rejected by exact document authorization in a DOS-alias/Unicode path  | Resolve the renderer file with native realpath and use the same pathToFileURL encoding for loading and authorization; regression covers Unicode, spaces, # and % | The corrected production installer must pass Windows CI; sender and main-frame identity checks remain exact    |

## Verification and release blockers

Run formatting/lint/strict typecheck, unit/architecture tests, Electron IPC/navigation/Node/CSP negative cases, complete Windows native lifecycle and shell matrix, packaged probe, actual installer/uninstall, accessibility audit and dependency audit. Preserve JSON reports and the exact source/artifact checksums. Linux tests cannot establish native Windows or signed-binary security. Windows execution for the new Phase 5 checks is pending until actual CI evidence is attached.

The release checklist keeps missing signing, actual Windows 10/11, Narrator, performance-budget review and owner approval as explicit blockers. There is no update client or publisher to activate accidentally. A future update/provider/signing implementation needs a new reviewed trust-boundary change. No unresolved critical/high code finding is silently waived by this report; a failing privacy, ownership, IPC or integrity gate blocks readiness.
